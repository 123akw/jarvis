## 一、各家值得抄的点与反例

> 来源说明：Dify 文档取自 docs.dify.ai 的 Markdown 版（2026-10-03），界面文案取自 GitHub `langgenius/dify` 的 `web/i18n/locales/zh-Hans/*.json`（官方中文），源码结构取自 `web/app/components/workflow/`。Langflow 同理（docs.langflow.org + `src/frontend/src/locales/zh-Hans.json`）。n8n 文案取自 `packages/frontend/@n8n/i18n/src/locales/en.json`。

### 1. Dify（工作流 / Chatflow）

值得抄：

1. **插入变量用 `/`（或 `{`）唤出下拉，选中后在文本里显示成「节点名 / 变量名」的小标签**，比如「User Input/draft」，用户看不到 `{{…}}` 原文；输入框里常驻一行灰字提示「按 '/' 键快速插入」。我们照搬：`/` 和 `{{` 都弹选择器，显示「AI 处理 · 文字」。【[Key Concepts](https://docs.dify.ai/en/learn/key-concepts.md)；[30 分钟上手](https://docs.dify.ai/en/quick-start.md)；中文文案 `common.insertVarTip`】
2. **「检查清单」（Checklist）**：顶栏一个带数字的按钮，列出「此节点尚未连接到其他节点」「{{field}} 不能为空」「必须添加{{node}}节点」，每条带「前往修复」，点了画布定位到该节点；全部解决时显示「所有问题均已解决」。这就是我们要的「就地提示 + 汇总」。【`panel.checklist*`、`common.needConnectTip`、`errorMsg.fieldRequired`、`panel.goToFix`】
3. **加节点三条路**：从块面板选、节点出口的「+」弹快捷面板（`nodes/_base/components/node-handle.tsx`、`next-step/`）、配置面板底部「下一步」区块列出下游并可「添加此工作流程中的下一个节点」。快捷面板打开即聚焦搜索框、Esc 关闭并把焦点还回、悬停 150ms 出预览卡。【`block-selector/README.md`；`panel.nextStep` / `panel.addNextStep`】
4. **运行追踪三栏：结果 / 详情 / 追踪**。追踪按执行顺序列出每个节点、耗时和数据流，失败节点直接给错误；每个节点的配置面板还有「上次运行」页签看该节点的输入 / 输出 / 用时。【[Run History](https://docs.dify.ai/en/cloud/use-dify/debug/history-and-logs.md)；[Single Node](https://docs.dify.ai/en/cloud/use-dify/debug/step-run.md)】
5. **一句话生成先出「计划」再出图**：生成弹窗下方给 4 个「试试这些」建议（模型生成、失败时退回固定列表、可「换一批」）；生成时先显示骨架 →「正在规划工作流……」→ 用真实节点图标列出计划 →「正在构建节点……」；改已有流程时先给「新增 2 · 删除 1 · 修改 1」的差异摘要再让用户「应用」。【`workflow-generator/example-prompts.tsx`、`generation-plan.tsx`、`graph-diff.ts`；`workflowGenerator.*` 中文】
6. **模板详情有「必须配置项」与「试用」**：探索页模板分类页签（推荐 / 写作 / 翻译 / 人力资源 …），点开有「试用」和「编排详情」两个页签，列出「必须配置项」，主按钮「从此模板创建应用」。对应我们的 `needs` 与预览弹层。【`explore.json`：`tryApp.requirements`、`tryApp.createFromSampleApp`】
7. **定时触发用可视化选择器，并显示「接下来 5 次运行时间」**，cron 只作为高级选项。【[Schedule Trigger](https://docs.dify.ai/en/cloud/use-dify/nodes/trigger/schedule-trigger.md)】

别学：

- **概念太多**：Workflow / Chatflow 两种应用、20 多种节点（参数提取器、变量聚合器、变量赋值、列表操作、文档提取器 …）、环境变量 / 会话变量 / 系统变量三套变量；块面板有「节点 / 工具 / 数据源 / 开始 / Snippets」五个页签。非技术用户看到就退。我们只留 7 种节点、一套「变量」。【[节点目录](https://docs.dify.ai/_llms/en/cloud.md)；`block-selector/README.md` 页签顺序】
- **出错默认直接停并给原始报错**，「默认值 / 失败分支」要用户自己去配。我们应当默认就把错误翻成人话并指出哪个节点、怎么改，不暴露 `error_type` 这类变量。【[Handle Errors](https://docs.dify.ai/en/cloud/use-dify/build/predefined-error-handling-logic.md)】

### 2. Langflow

值得抄：

1. **空画布欢迎页**：新建时先问「你想打造什么？」，下面是一个大输入框「请描述你的工作流程……」+「发送」，再下面「或者从模板开始：」两三个快捷模板 +「浏览更多…」+「空白流」。这就是「一句话生成 + 模板」合并成一个起步页。【`flowBuilderWelcome.*`（zh-Hans.json）；`components/core/flowBuilderWelcome/`】
2. **模板弹窗左侧分类**：「开始」（精选 3–4 个带大图的入门卡）/「所有模板」/ 按用例（助手、分类、编码、内容生成、问答 …），右侧网格 + 搜索；左上角固定「从头开始」。【`modals/templatesModal/index.tsx`；`templatesModal.*`】
3. **节点上直接「运行组件」和「检查输出」**：每个组件右上有 ▶ 按钮单独运行到它为止，输出口旁有眼睛图标看产出；不用跑整条。【[Components](https://docs.langflow.org/concepts-components)；`node.runComponent` / `node.inspectOutput`】
4. **端口按数据类型着色，悬停端口显示连接说明，点端口直接「搜索可接的组件」**（列表已按能不能接过滤）。我们不需要按类型着色（变量都是文字 / 列表），但「点出口 → 只列能接的节点」值得照做。【[Components](https://docs.langflow.org/concepts-components)】
5. **默认只显示必填和常用参数**，其余收进右侧「组件参数」面板（可调哪些参数露在卡片上）。我们的节点卡只露 1–2 行摘要，参数全在右侧面板。【同上；`inspectionPanel.*`】
6. **AI 助手改流程时逐条播报「正在添加 X…」「正在连接组件…」「正在配置 X…」，每次改动可「撤销此编辑」**。一句话生成的过程提示可以照这个写。【`assistant.buildTasks.*`、`assistant.revert.*`】

别学：

- **机翻中文**：「空白流」「特工」「成品检验」「您最喜爱的特工运输新方式」——术语直译、不通顺。我们所有文案要中文母语者口吻。【`page.welcomeDescription`、`shortcuts.name.outputInspection`（zh-Hans.json）】
- **以开发者为中心**：卡片上满是 Code / Freeze / Tool Mode / API 开关，Playground 只对含「Chat Input」的流程好用，非聊天流程要去调 API。我们的运行面板要对任何流程都能用：按开始字段自动生成表单。【[Playground](https://docs.langflow.org/concepts-playground)】

### 3. n8n / 扣子（Coze）/ ChatGPT Agent Builder

**n8n** 值得抄：

1. **加节点面板用问句当标题**：从出口点「+」→「What happens next?」（接下来做什么？）；新流程第一步→「What triggers this workflow? / When should this workflow run?」（什么时候运行？），选项写成「Trigger manually — 点按钮运行，适合刚上手」「On a schedule — 每天、每小时或自定义间隔运行」。【n8n `en.json`：`nodeCreator.triggerHelperPanel.*`】
2. **「过期」标记**：节点跑过之后又改了配置 / 连线，节点边框变黄、✓ 换成黄色三角，悬停说明「配置已改，再运行结果可能不同」。我们的运行态也该有「结果已过期」，避免用户对着旧结果困惑。【[Understand dirty nodes](https://docs.n8n.io/build/understand-workflows/understand-executions/understand-dirty-nodes.md)；`node.dirty`】
3. **上游没数据时给一个按钮**：「No input data — Execute previous nodes」。我们的变量选择器在上游还没跑过时也可以给「先运行一次看看会有什么」。【`ndv.input.noOutputData.*`】
4. **AI 建流程三步**：选示例或描述 → 实时阶段反馈 → 列出「还需要你配置的凭据 / 参数」再用对话继续改。【[AI Workflow Builder](https://docs.n8n.io/build/ways-of-building-workflows/ai-workflow-builder.md)】

n8n 别学：节点数据面板默认 JSON / 表格 / Schema 三视图、表达式模式 `{{ $json.x }}`，完全是给工程师的；模板库跳到外站浏览。

**扣子（Coze）** 值得抄（官方帮助中心为前端渲染页，以下据社区教程与产品界面整理，链接为二手来源）：

1. **参数「引用 / 输入」二选一**：每个参数左边一个小下拉，选「引用」就从上游节点的输出里点选，选「输入」就直接填文字。对不懂变量的人很直观。【[人人都是产品经理：扣子工作流教程](https://www.woshipm.com/ai/6258270.html)；[CSDN：扣子多节点流程](https://gitcode.csdn.net/6aa0e0d01a35784c84209897.html)】
2. **底部浮动工具条**放「添加节点」「试运行」、缩放与「优化布局」，画布上方不堆按钮。【同上】
3. **试运行时每个节点右上角出现「运行成功 · 耗时」徽标，可展开看本节点输入 / 输出**；失败节点标红并给原因。【同上】

扣子别学：变量名要用户自己起、区分大小写、没有自动补全，写错就「变量未定义」。我们的变量由系统按节点自动产生，用户只点选。【[CSDN](https://gitcode.csdn.net/6aa0e0d01a35784c84209897.html)】

**ChatGPT Agent Builder** 值得抄：模板起步或空白起步；**自动保存**；「预览」里可以带样例文件跑一遍并**看着每个节点依次执行**；发布 = 打一个版本快照。【[Agent Builder 文档](https://developers.openai.com/api/docs/guides/agent-builder)】

别学 / 注意：OpenAI 已宣布 Agent Builder 将于 **2026-11-30 停服**，节点间是「有类型的连线」、要求理解数据契约——对我们的用户太重；参考它的交互，不参考它的概念。【同上】

### 4. 新手引导：产品与库

**产品做法**

| 产品 | 值得抄 | 别学 / 注意 |
|---|---|---|
| Dify「认识 Dify」分步引导 | ① 状态存**服务端**（`completed_task_ids`、`skipped`），换设备不重复出现，前端先乐观更新再对账。② 用**具名锚点注册表**（`STEP_BY_STEP_TOUR_TARGETS`）而不是写死 CSS 选择器，和我们的 `data-tour` 同一思路。③ 每步分「看一眼」（walkthrough）和「要你动手」（action）两类，动手步只让目标可点（`interactionPolicy: 'target-only'`）。④ 跳过后给一条**恢复提示**：「引导已隐藏。可随时在 帮助 → 分步引导 中重新开启。」⑤ 标题旁写预期时长「快速浏览 — 大约 5 分钟」，步骤写「第 2 步 / 共 5 步」，按钮用「知道了」。【`web/app/components/step-by-step-tour/state.ts`、`target-registry.ts`；`onboarding.json`】 | 引导覆盖首页、Studio、知识库、集成四大块，近 50 个锚点，太长；我们每页 ≤7 步。 |
| Linear | **不做气泡导览**，给一份「熟悉 Linear」的任务清单（建一个事项、用 ⌘K、设优先级），任务本身就是真实数据，做完就会了；约 7 步、60 秒。【[Supademo：Linear 引导拆解](https://supademo.com/content/plg-onboarding-gallery/linear)；[Impeccable：onboard](https://www.impeccable.style/docs/onboard)】 | 只适合高意愿、懂行的用户；我们的用户需要被「指着看」，所以用导览 + 示例流程两手。 |

## 二、按区域的落地清单

> 每条开头标注负责的代理：〔画布〕〔列表页〕〔后端〕（引擎 / 好用层）〔引导〕。数值沿用第十七轮令牌：间距取 4 的倍数，圆角 8 / 12 / 16，动效 160 / 240 ms，`--m-ease`。

### 1. 画布与节点卡

1. 〔画布〕**从左往右排**：入口在节点左侧、出口在右侧（Dify、Langflow、n8n 都这样）。打开时 `fitView({padding: 0.2})`，缩放 0.25–2。底纹用点阵：`<Background variant="dots" gap={16} size={1} />`，点的颜色取 `--jv-border` 的 50%。【Dify `operator.zoomToFit`「自适应视图」】
2. 〔画布〕**节点卡宽 240**（Dify 同宽）。头部：24px 图标瓦片（圆角 8，按类型着色）+ 标题 14/600（单行省略）+ 右侧状态位。正文：1–2 行配置摘要（12/16，次要色），例如「把 开始 · 文字 交给 AI：提炼 3 条要点」「查 {城市} 的实时天气」。颜色只上图标瓦片，卡片本身保持中性（发丝边、无阴影）。
3. 〔画布〕**类型色**（只用于图标瓦片和条件出口）：开始 = 绿、AI 处理 = 紫、插件工具 = 蓝（用插件自己的图标）、条件分支 = 橙、文本拼接 = 青、积木 = 灰蓝、结束 = 绿。深 / 浅色各给一套 `--jv-node-*` 令牌。
4. 〔画布〕**问题就地标**：缺必填 → 卡片底部一行橙字「还缺：城市」；没连上 → 「还没连上，这一步不会运行」（Dify `common.needConnectTip`）；变量失效 → 「用到的『AI 处理 · 文字』已经不在了」。同时汇总进顶栏「检查」按钮的数字（见第 5 节）。
5. 〔画布〕**运行态 5 种**：运行中 = 2px 强调色描边 + 头部转圈；完成 = 绿 ✓ +「1.2 秒」小标签；出错 = 红描边 + ✕ + 一行原因；没走到（跳过）= 整卡透明度 .45 +「没走到」；**结果已过期**（跑完后又改了这一步或它的上游）= 黄三角，悬停说明「改过了，再运行结果可能不同」。【n8n dirty node；Dify `tracing.status.*`】
6. 〔画布〕**连线**：贝塞尔曲线，1.5px，次要色；选中 / 悬停 2px 强调色，中点出现「＋」（在两步之间插一个节点）和「✕」（删除连线）。运行中把正在流入的那条设 `animated`（虚线流动），减弱动效时改为常亮强调色。
7. 〔画布〕**连线规则即时提示**（用 `isValidConnection` 拦截，不弹窗，跟手出一条 toast）：连成圈 →「这样会绕成圈，流程会停不下来」；连进「开始」→「『开始』前面不能再接东西」；从「结束」往外连 →「『结束』后面不能再接」。
8. 〔画布〕**删除有下游引用的节点要确认**：「后面有 2 个节点用到了它的结果，删除后那些地方会变成空的。仍要删除？」（Dify `remove-effect-var-confirm.tsx` 同款）。「开始」不可删，菜单里置灰并说明。
9. 〔画布〕**右下角缩放条**：「− 100% ＋ ｜ 适配 ｜ 整理」；不放小地图（≤30 个节点用不着，还多一个概念）。快捷键照 Dify：⌘Z / ⌘⇧Z、⌘S、Delete、⌘D 复制、⌘1 适配视图、空格 + 拖动平移；「整理」不给快捷键（Dify 用 ⌘O，在浏览器里与「打开文件」冲突）。快捷键在输入框里不生效。【[Dify Hotkeys](https://docs.dify.ai/en/cloud/use-dify/build/shortcut-key.md)】
10. 〔画布〕**自动整理**（`graph.js` 自写）：按拓扑序分层，层宽 240、层间距 80、同层节点间距 40；条件分支的下游按 case 顺序从上到下排、「否则」在最下；整理后 `fitView`，并能撤销。
11. 〔画布〕**撤销栈 ≤50 步**；输入框连续打字 500ms 内合并成一步；拖动只在松手时记一步。顶栏保存状态三态：「已保存」「保存中…」「有改动」；离开页面时有未保存改动用浏览器 `beforeunload` 提醒。Agent Builder 和 Dify 都是自动保存，**建议 2 秒防抖自动保存**（契约写的是「保存状态」，是否自动保存需主控拍板）。

### 2. 节点面板与加节点方式

1. 〔画布〕**左侧面板宽 260，可收起**。顶部搜索框（按 `/` 聚焦），下面分组：「最近用过」（localStorage，最多 5 个，没有就不显示）→ 基础（AI 处理、条件分支、文本拼接、结束）→ 插件工具（按插件分类折叠：办公、生活、资讯、文档、发送 …）→ 技能 → 积木。分组可折叠，折叠状态存 localStorage（Dify `storage.ts` 同款）。
2. 〔画布〕**面板行**：32px 图标 + 名称 + 灰色插件名；悬停 150ms 后在右侧弹预览卡：一句话、需要填什么（来自 `args`）、产出什么（「文字」「条目列表」）。【Dify 块面板 `PreviewCardTrigger delay={150}`】
3. 〔画布〕**不可用的工具也列出**，置灰 + 🔒，点它弹出原因（`reason`）和按钮「去加插件」，不允许拖进画布。
4. 〔画布〕**三种加法**：
   - 拖到画布：放在松手处；若松在某条连线上，就插进这条线中间。
   - 点一下：接在当前选中节点后面并自动连线，位置 = 选中节点右侧 320px（若被占就往下错 120px）；没选中就接在最后一个非结束节点后面。新节点自动选中并打开右侧配置面板。
   - 出口的「＋」：悬停节点时出口变成 16px 圆形「＋」；点它弹出快捷面板（320×420，标题用问句「接下来做什么？」，打开即聚焦搜索，Esc 关闭并把焦点还回「＋」）。从条件分支某个出口点「＋」，新节点就接在那个分支上。从出口拖线到空白处松手，也弹同一个快捷面板，选中后节点出现在松手处。【n8n「What happens next?」；Dify `node-handle.tsx`；React Flow `onConnectEnd`】
5. 〔画布〕**快捷面板只列能接的**：结束节点后面不弹；「开始」不出现在列表里。
6. 〔画布〕**新流程默认就有「开始」和「结束」两块**，中间空着时画布正中放一张提示卡：「从左边拖一个节点进来，或点『开始』右边的 ＋」，加了第一个节点后消失（这是情境提示，与导览无关，见 NN/g）。

### 3. 配置面板与变量选择器

1. 〔画布〕**右侧面板宽 360**，240ms 滑入；头部：图标 + 可点改的标题 + 类型小字 + 关闭；下面两个页签「设置」「上次结果」（Dify「上次运行」）。底部固定「下一步」区：列出直接下游，外加「＋ 添加下一步」。【Dify `panel.nextStep`】
2. 〔画布〕**插入变量两种入口**：① 在可写变量的输入框里打 `/` 或 `{{` 弹出选择器；② 输入框右下角常驻一个「{x} 插入变量」小按钮（手机上只有这个）。输入框里灰字提示「打 / 插入前面步骤的结果」。【Dify `common.insertVarTip`「按 '/' 键快速插入」】
3. 〔画布〕**选择器内容**：只列祖先节点，离当前节点越近越靠上；每个节点一组（图标 + 标题），下面是它的产出，用人话：文字 / 条目列表 / 标题 / 链接 / 分段 / 文件；最后一组「系统」：今天日期、现在时间、星期几；在逐条处理里多一组「当前这一条」。支持键入过滤，↑↓ 选、回车插入、Esc 关。上游一个都没有时显示「前面还没有能用的结果，先在左边加一个节点」。
4. 〔画布〕**变量在框里显示成小标签**「AI 处理 · 文字」（底色 = 来源节点类型色的 12%），存储仍是 `{{n1.text}}`；退格一次删掉整个标签；源节点改名后标签跟着变。实现上不加依赖：用 `contentEditable` 的 div，标签是 `<span contenteditable="false" data-var="n1.text">`，序列化时遍历 DOM；粘贴一律转纯文本。失效引用显示成红色标签「已失效」。
5. 〔画布〕**插件工具参数表单由 `args` 生成**：`label` 作字段名、`description` 作字段下灰字、`required` 标「必填」、`enum` 变下拉；文字类字段都支持插变量。默认值预填：若开始节点有同名 / 同义字段（如 city），自动填 `{{start.city}}` 并在字段下注明「已自动接上『开始 · 城市』」。
6. 〔画布〕**AI 处理节点**：字段名不叫 Prompt，叫「要 AI 做什么」，占位符给例子「把 {开始 · 文字} 整理成 3 条要点，每条不超过 20 字」；「输出成」二选一：一段文字 / 一条条的清单（= `output: text | list`）；可选「用技能」下拉（技能插件）。
7. 〔画布〕**「上次结果」页签**：显示这一步实际收到的内容（变量已替换后的文字）、产出预览、用时；没跑过就显示「还没运行过，点右上角『运行』试一次」+ 按钮。【Dify Single Node「Last run」；n8n `ndv.input.noOutputData`】
8. 〔画布〕**不可用节点**在面板顶部放一条黄色提示：「这个智能体还没装『查天气』，装上才能运行」+「去加插件」按钮。

### 4. 条件分支

1. 〔画布〕**面板结构**用中文「如果 / 否则如果 / 否则」，不出现 IF / ELIF / ELSE。每个情况有可改的名字（默认「情况 1」「情况 2」），这个名字就是节点出口上的标签。「否则」永远在最后、不能删。【Dify If-Else】
2. 〔画布〕**每条规则一行三格**：［选变量 ▾］［比较方式 ▾］［值］。比较方式：包含 / 不包含 / 等于 / 不等于 / 是空的 / 不是空的 / 大于 / 小于 / 大于等于 / 小于等于；选「是空的 / 不是空的」时隐藏「值」；大于 / 小于类在下拉里注明「按数字比」。
3. 〔画布〕**多条规则的关系**用一个切换「全部满足 / 满足任一」，不出现 AND / OR。
4. 〔画布〕**节点卡上每个情况一行、一个出口**：行内是摘要「如果 AI 处理 · 文字 包含『紧急』」，出口点在这一行的右边；最后一行「否则」。情况建议 ≤5 个（超过给提示，不硬拦）。
5. 〔画布〕**运行时**：选中的出口那条线亮起，没走到的分支整串变暗并标「没走到」；运行面板里条件节点那行写「走了：情况 1（紧急）」。
6. 〔后端〕**文字比较默认去掉首尾空白、不分大小写**；大于 / 小于两边都能转成数字才比，否则这条规则算不满足，并在节点结果里写一句「『abc』不是数字，没法比大小」。
7. 〔列表页 / 后端〕模板里示范「先让 AI 判断，再分支」：AI 处理输出「只回答：好评 / 差评 / 咨询」，条件分支用「等于」接住。这样不懂规则的人也能做智能分流（相当于 Dify 的问题分类器，但不新增节点类型）。

### 5. 运行与追踪

1. 〔画布〕**顶栏右侧**：「检查 ·2」（有问题时才出现，橙色数字）＋主按钮「运行」。点「检查」弹出问题清单，每条一句人话 +「去改」，点了画布居中到该节点并打开设置。点「运行」时有问题就先弹这个清单，不发请求；有未保存改动就先保存（按钮文字短暂变成「保存中…」）。【Dify `panel.checklist*`「前往修复」】
2. 〔画布〕**运行面板**替换右侧配置面板（宽 400），三段：输入 → 过程 → 结果。输入表单按开始节点字段生成（文件字段是拖放区），记住每个流程上次填的值（localStorage）；按钮「开始运行」。
3. 〔画布〕**过程**：按执行顺序列出节点行（图标、标题、状态、用时），收到 `node_start` 时加一行转圈，`node_done` 变 ✓ 并显示 `summary`，点开看 `preview` / 完整产出（文字可复制、条目列表逐条、链接成按钮）；`node_skip` 行灰掉写「没走到」；`node_error` 行红色自动展开，写原因 + 按钮「去改这一步」。点任意一行，画布居中到对应节点；**画布不自动跟着平移**（会晕）。【Dify Tracing；扣子试运行徽标】
4. 〔画布〕**结果**：跑完把结果卡顶到面板最上面：状态行「完成 · 用时 8.4 秒 · 6 步」，Markdown 正文，链接做成按钮（「打开飞书文档」「打开结果网页」），一个「复制结果」。失败时状态行写「第 3 步『查天气』出错了」。
5. 〔画布〕**运行中**主按钮变「停止」（断开 SSE + 调用停止）；连接断了显示「连接断了，这次结果会保存在运行记录里」，并改为轮询 `GET /runs?limit=1`。
6. 〔后端〕**报错一律三段式人话**：哪一步 + 怎么了 + 怎么改。例：「『查天气』没查到：城市『北京市朝阳』没找到。把城市改成『北京』再试。」不要把异常类名、HTTP 码、栈原样给前端（Dify 默认给原始报错，是反例）。
7. 〔后端〕`node_done.output.text` 截到 2000 字时末尾加「…（已截断，完整内容见最终结果）」，前端据此显示提示。
8. 〔列表页〕**运行记录抽屉**：每条一行「今天 08:00 · 完成 · 8.4 秒 · 定时」，点开是同一套「过程 + 结果」只读视图，底部「用这次的输入再跑一次」。【Dify Run History：结果 / 详情 / 追踪】

### 7. 一句话生成

1. 〔列表页〕**输入**：占位符照契约；≥6 个字才能提交，回车提交、⇧回车换行；下面「试试这些」4 个药丸（固定列表即可，Dify 是模型生成 + 固定兜底，我们先做固定）+「换一批」。示例：「每天早上把天气和日程发到飞书」「把会议记录整理成待办」「顾客差评先分类再写回复」「把长文章拆成学习卡片」。
2. 〔列表页〕**等待态说实话**：不做假进度。显示一个节点清单形状的骨架 +「正在规划流程……一般要 5–15 秒」，可「取消」。（Dify 删掉了猜时间的假阶段，改为真实「规划 → 构建」；我们接口不流式，就只显示一个阶段。）【Dify `generation-plan.tsx`】
3. 〔列表页〕**预览弹层**：缩略图 + 节点清单（图标 + 标题 + 一句摘要）+ `notes`（如「需要先绑定飞书」「你没说发到哪，我先放了『结果网页』」）；`source: "template"` 时小字写「没完全理解，先按最接近的模板『早安简报』给你」。按钮：「打开编辑」（主）、「换个说法」（回到输入框并保留原文）。名字可在弹层里直接改。
4. 〔后端〕**生成约束**：提示词里只给节点目录（key、标题、一句话、参数名），要求模型输出「节点清单 + 连线」，不让它写 position；服务端校验失败时把错误人话喂回去**重试一次**，再失败才退回模板（按描述与模板 name/summary 的关键词重合度选最接近的）。工具名不在目录里 = 删掉该节点并在 `notes` 里说明。【Dify 生成器错误码 `UNKNOWN_TOOL` / `GRAPH_CYCLE` / `UNRESOLVED_REFERENCE` 都是我们校验要覆盖的情况】
5. 〔后端〕`notes` 最多 3 条，每条 ≤30 字；不要说「已为您生成」这类废话，只说用户需要知道或要做的事。

### 8. 定时 / 触发

1. 〔列表页〕**弹层**：顶部开关「定时运行」；「重复」分段按钮「每天 / 工作日 / 每周」，选「每周」出现「一 二 三 四 五 六 日」单选药丸；「时间」原生时间框；下面一行实时预览「下次运行：明天（周六）08:00」，再小字列出之后 2 次（Dify 显示接下来 5 次，我们 3 次够了）。**不出现 cron**。【Dify Schedule Trigger 可视化选择器；n8n「On a schedule」】
2. 〔列表页〕**预填输入**按开始字段生成；必填没填不能开启，提示「定时运行时没人填，先在这里填好」。文件类字段不支持定时：显示「定时运行不能带文件」并灰显，若该字段必填则整个开关不可开并说明原因。
3. 〔列表页〕**通知**：「发到飞书」「桌面通知」两个勾选；飞书没绑定时灰显 +「还没绑定飞书，去绑定 ›」。
4. 〔列表页〕**卡片标记**：时钟图标 +「每个工作日 08:00」；上次定时运行失败时标签变红「上次定时运行失败」，点开运行记录。
5. 〔后端〕**时区固定按服务器的北京时间**，并在 `label` / `next_run_at` 里体现；`next_run_at` 用 ISO 带时区。`busy` 顺延一分钟、重启不补跑超过 1 小时的，照契约。
6. 〔后端〕**建议（需主控决定）**：同一触发器连续失败 5 次自动暂停，并按 notify 发一条「『早安简报』连续 5 次没跑成，已暂停定时。原因：…」，避免每天刷屏报错。

### 9. 手机端（<760px）

1. 〔画布〕**列表式编辑**：节点卡按拓扑序竖排，卡间一条细竖线，线上一个「＋」可在中间插入；条件分支在卡下面按情况缩进分组，每组头写「情况 1（紧急）」「否则」。
2. 〔画布〕**点卡片 → 底部弹层配置**（最高 85vh，顶部拖动条，上圆角 16，可下滑关闭）；变量只用「{x} 插入变量」按钮，弹出底部列表，不依赖打 `/`。
3. 〔画布〕**加节点**：底部弹层里放同一个节点面板（搜索 + 分组），选中后接在当前位置。手机上**不支持拖拽**。
4. 〔画布〕**运行**：底部固定条「运行」主按钮；运行过程用全屏弹层，结构同桌面三段。
5. 〔画布〕**顶部切换**「步骤 / 看图」：看图 = 只读画布，可双指缩放、不能编辑。所有点击目标 ≥44×44。
6. 〔列表页〕模板卡、我的流程卡在手机上改无边框列表行（行高 72），一句话生成输入框置顶。

### 10. 新手引导（flows-home / flows-editor）

1. 〔引导〕**何时自动开始**：`ready` 为真、进场动画结束（`introPlaying()` 为假）后再等 600ms，且页面上没有打开的弹层；同一时刻只跑一个导览。用户在 3 秒内已经开始操作（拖动、输入）就推迟到下次进入，不打断（NN/g：用户想马上动手）。
2. 〔引导〕**卡片**：宽 320（手机为底部全宽卡），标题 16/600、正文 14/22 一两句；底部左「跳过」文字按钮，右「上一步」「下一步」，末步「完成」；步骤点 +「2 / 6」。第一步标题旁写「约 1 分钟」。【Dify「快速浏览 — 大约 5 分钟」「第 2 步 / 共 5 步」】
3. 〔引导〕**跳过后的恢复提示**：底部 toast 4 秒「引导已收起，随时点右上角『新手引导』再看」。【Dify `skipRecovery.message`】
4. 〔引导〕**flows-home（3–4 步）**：
   1. `flows-compose` —「说一句话就能搭好」：写下你想自动化的事，比如「每天早上把天气发到飞书」，贾维斯帮你搭好，你再改。
   2. `flows-templates` —「或者从模板开始」：挑一个最接近的，点「用这个模板」，缺什么会告诉你。
   3. `flows-new` —「也可以自己从头搭」：打开空白画布，一步一步拼。
   4. `flows-list` —「做好的流程都在这」：能直接运行、看运行记录、设成每天自动跑。（列表为空时跳过这一步）
5. 〔引导〕**flows-editor（6 步，必要时第 7 步）**：
   1. `flow-canvas` —「这是你的流程」：每个方块是一步，连线决定先后，从左往右依次运行。
   2. `flow-palette` —「从这里拿节点」：AI 处理、插件工具、积木都在这。拖到画布上，或者点一下就接在选中的那一步后面。
   3. `flow-node-start` —「从『开始』出发」：这里决定运行时要填什么（一段文字、一个文件……）。点它右边的 ＋，直接加下一步。
   4. `flow-config` —「点一下节点，在右边改设置」：每一步要做什么都在这里填；没填完的会标出来。（此步前若没有选中节点，导览代为选中第一个非开始节点；没有就选中开始节点）
   5. `flow-var` —「用上一步的结果」：在输入框里打 /，或点「插入变量」，就能把前面步骤的结果放进来，比如「AI 处理 · 文字」。
   6. `flow-run` —「运行看看」：填好内容点运行，每一步会依次亮起，点开能看到每一步做了什么。
   7. （可选）`flow-save` —「记得保存」：⌘S 或点这里；回到「我的流程」还能设成每天自动运行。
   - 完成卡：「好了！随时点右上角『新手引导』再看一遍。」
6. 〔引导〕**手机版 flows-editor** 去掉 `flow-palette` 与 `flow-canvas` 两步（手机是列表编辑），改成「点卡片改设置」「点 ＋ 加一步」「运行」3 步；底部卡片不遮挡目标（目标在下半屏时卡片放到顶部）。
7. 〔引导〕**存储**：登录用户先写 localStorage（立即生效）再 `PUT /api/onboarding`（失败静默重试一次）；读取时服务端优先，合并本地记录（任一处看过即看过），避免网络慢时重复弹出。游客只用 localStorage。读写都包 try/catch。【Dify 服务端存 `completed_task_ids` / `skipped`】
