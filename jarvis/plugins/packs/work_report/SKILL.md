# 周报月报
用户说「帮我写周报 / 月报」「把这些记录整理一下交给领导」「要述职了理个提纲」时，按下面的规矩做。

## 先问清楚（缺什么问什么，一次最多问两个）
- 写给谁看：直属领导、部门群还是全公司；有没有固定模板；
- 这段时间干了哪些事：让用户把聊天记录、待办、随手记直接贴进来，乱一点没关系。
用户说「你看着写」就按下面的默认格式直接写。

## 怎么做
1. 先把流水账归类：同一件事的多条记录合成一条，按「项目 / 客户 / 工作类型」分组。
2. 每条都往「结果」上写：做了什么 → 到了什么程度 → 带来什么效果。「跟进客户」要写成「跟进 3 家客户，1 家签约」这种样子；用户没给数字就写【待补充：数量】，不要自己编。
3. 挑出最重要的 3 件放最前面，琐事合并成一句「其他：……」。
4. 问题和风险单独列：卡在哪、需要谁支持、什么时候之前要解决。
5. 下步计划写成能检查的事：做什么、做到什么程度、哪天完成。
6. 月报、季度述职多一段「数据对比」（和上月 / 目标比）和「经验与反思」，用户没给数据就只列要填的项。

## 输出格式
```
【本周重点】（3 条以内，一条一句话）
【完成情况】按项目分组，每条：事项 — 结果 — 进度
【数据】（有就写，没有写【待补充】）
【问题与需要的支持】
【下周计划】事项 / 完成标准 / 时间
```
- 周报控制在一屏能看完（约 300–500 字），月报可以长一点；
- 发群里的版本去掉内部细节，给领导的版本可以多写问题和建议，用户没说就只给一版。

## 注意事项
- 不夸大、不编造数据、客户名、金额；只用用户给的材料，缺的用【待补充】占位，最后列出要补的项。
- 不写「圆满完成」「取得重大突破」这类空话，换成具体结果。
- 涉及薪资、绩效、人事评价的内容，提醒用户注意发送范围。
- 用户要改时，只改他指出的那一段，别整篇重写。
